# Veileder · Julie

## Hovedmål og tegn på suksess

Deltakerne lærer en praktisk arbeidsmåte de kan bruke i kundeprosjekter eller egne prosjekter, og får lyst og trygghet til å fortsette. Læring relevant for markedet og engasjement er førende.

| Kriterium        | Slik sjekker du det                                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------------------------------------- |
| Overføringsverdi | Alle beskriver én situasjon i et prosjekt der diff, commit eller gjennomgang er nyttig.                             |
| Mestring         | Minst 80 % gjør en synlig endring, lager commit og forklarer den. Tell personer, også når de jobber i par.          |
| Selvstendighet   | Alle som rekker det velger én egen forbedring uten å følge en full oppskrift. Noter hvem som trenger videre støtte. |
| Engasjement      | Minst 60 av de 90 minuttene er satt av til å prøve, diskutere og hjelpe hverandre.                                  |
| Videre bruk      | Alle får guiden og velger et konkret neste steg. Spør om nytte og lyst til å fortsette på slutten.                  |

GitHub-deling er et viktig læringspunkt. Hvis tilgang stopper noen, registrer dette separat; lokal Git-mestring teller fortsatt, og delingen tas igjen etterpå.

- [ ] Del oppsettsguiden tidlig og be folk teste 450 − 299 = 151.
- [ ] Test en fersk kloning med `npm ci`, `npm test`, `npm run build` og `npm run dev`.
- [ ] Få en kollega til å teste på Windows. Egen Mac-testing erstatter ikke dette.
- [ ] Bekreft lesetilgang OG rett til å publisere egne branches for deltakerne. Sjekk SSO. Ikke gjør repoet offentlig som snarvei.
- [ ] Hvis dere velger forks: test at organisasjonen faktisk tillater det, og oppdater deltakerinstruksen ved behov.
- [ ] Hold `main` stabil. Test selv én branch → push → PR med en annen konto eller en kollega.
- [ ] Åpne appen, guiden og Source Control før introen. Ha løsningsforslaget tilgjengelig.
- [ ] Avtal hvem som hjelper med oppsett, og finn makkere til dem som ønsker det.
- [ ] Bestill pizza og avklar levering, antall og kostbehov.

Ved 120 minutter: legg til en demonstrasjon av å reversere en commit og en liten mergekonflikt i et separat øvingsrepo/egen branch. Ikke introduser konflikter i felles `main` midt i økten.

## Reserveplan

- **Maskinoppsett stopper:** Pararbeid på en fungerende maskin. Begge skal få bruke tastaturet.
- **GitHub er utilgjengelig:** Lokale branches og commits virker. Gjennomgå diff i par. Fullfør PR senere.
- **For lite tid:** Prioriter synlig endring, diff, commit og forklaring. Vis PR i fellesskap hvis egen deling ikke lar seg gjennomføre.
- **Stor nivåforskjell:** Nybegynnere gjør nivå 1; erfarne tar nivå 3 eller hjelper en makker med spørsmål. Hjelperen overtar ikke oppgaven.
- **Noen sitter helt fast i appen:** Bruk fasiten til hurtigknappene. Lagre egne filer før dere erstatter noe. Unngå hard reset.

## Tre avslutningsspørsmål

1. Hva fikk du til, og hva er forskjellen på lagre, commit og push?
2. Hvor nyttig er dette i et prosjekt du jobber med, fra 1–5? Gi ett eksempel.
3. Har du lyst til å fortsette, fra 1–5, og hva blir ditt neste steg?

Noter antall som gjennomførte og eventuelle tilgangshindre. Bruk dette til å avgjøre om neste økt skal være mer Git eller utrulling til sky.
